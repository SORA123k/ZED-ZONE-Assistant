## 2. 实验 A：`HealAllBodyPartInjuries()`

### 2.1 调用前后（同一帧内快照）

| 部位 | 调用前 hp/max | 调用后 hp/max | `isWounded` | `isFullyRecovered` |
|---|---|---|---|---|
| 头部 | 108 / 108 | 108 / 108 | 0 → 0 | 1 → 1 |
| **躯干** | **22.428 / 138** | **138 / 138** | **1 → 0** | **0 → 1** |
| **左臂** | **109.558 / 118** | **118 / 118** | 0 → 0 | **0 → 1** |
| 右臂 | 118 / 118 | 118 / 118 | 0 → 0 | 1 → 1 |
| **左腿** | **64.13 / 128** | **128 / 128** | **1 → 0** | **0 → 1** |
| **右腿** | **64.385 / 128** | **128 / 128** | **1 → 0** | **0 → 1** |

**整体 HP：2160 → 2160（完全不变）** ✅
**buff 数量：3 → 0** ⚠（见 §2.2）

### 2.2 七项验证结论

| # | 验证项 | 结果 | 证据 |
|---|---|---|---|
| 1 | 是否真正修改六个部位的 HP | ✅ **是** | 4 个受伤部位各自回到**自己的 maxHP**（138/118/128/128，各不相同 → 不是统一常量） |
| 2 | 是否修改 `isWounded` | ✅ **是** | 躯干/左腿/右腿 1→0 |
| 3 | 是否修改 `isBleeding` | 🟡 **无法观察** | 全程 `bleeding=0`，没有流血样例 |
| 4 | 是否修改 `isFullyRecovered` | ✅ **是** | 4 个部位 0→1 |
| 5 | 是否修改绷带 | ✅ **是（有延迟）** | 调用后 0s/2s `bandaged=1`，**6s 时变为 0** |
| 6 | 是否只影响当前玩家 | 🟡 **设计上只影响玩家**，未实测他人 | 实例方法；未对他人调用 |
| 7 | 是否存在视觉与数据不同步 | 🟡 **未验证** | 数据已改；贴图需人工观察 |

### 2.3 【重要】副作用：Buff 被清除

`buffCount` 从 **3** 变为 **0**。

- 合理猜测：清掉了伤口类 Debuff（21–24）或恢复类 Buff（34–37）——**属预期**；
- 但**无法确认**清掉的是哪几个（本轮未记录 Buff ID）；
- **若其中包含有益 Buff，则属意外副作用**。

→ 列为新风险 **R13**，下一阶段必须记录 Buff ID 再判断。

### 2.4 判定

> **`HealAllBodyPartInjuries()` 是真正的 HP 恢复接口，不是纯视觉接口。**
> 原风险 R3（"可能只改视觉"）**解除**。
> 它满足"全部肢体恢复"的核心要求：逐个恢复到各自动态 maxHP、同步伤口状态、不影响整体 HP。

## 3. 实验 B：`RefreshBodyPartRecoveryBuff(5)`（目标：右腿）

### 3.1 调用前后

| 部位 | 调用前 | 调用后（同帧） |
|---|---|---|
| 躯干 | 22.428 / 138 | 22.428 / 138 |
| 左臂 | 109.558 / 118 | 109.558 / 118 |
| 左腿 | 64.13 / 128 | 64.13 / 128 |
| **右腿（目标）** | **64.385 / 128** | **64.385 / 128** |
| 整体 HP | 2160 | 2160 |
| **buff 数** | **3** | **3** |

**DELTA 变化部位数 = 0 —— 六部位数据完全未变。**

### 3.2 时间序列（自然恢复对照）

| 时刻 | 躯干 | 左腿（对照） | **右腿（目标）** | buff |
|---|---|---|---|---|
| 0s | 22.428 | 64.130 | 64.385 | 3 |
| +2s | 22.428 | 64.130 | 64.385 | 3 |
| +6s | 22.428 | 64.130 | 64.385 | 3 |
| +12s | 23.164 | 64.813 | 65.068 | 3 |
| +30s | 24.513 | **66.064** | **66.319** | 3 |

**关键对照计算（0s → 30s）**：

| 部位 | 增量 | 占各自 maxHP |
|---|---|---|
| 左腿（**未指定**） | +1.934 | 1.51% |
| **右腿（已指定）** | **+1.934** | **1.51%** |
| 躯干 | +2.085 | 1.51% |
| 左臂 | +1.783 | 1.51% |

→ **目标与对照的涨幅完全一致（百分比也一致）**，且完全没有 Buff 增减。

### 3.3 判定

> **`RefreshBodyPartRecoveryBuff(bodyPartId)` 在本场景下没有任何可观测效果。**
> 它很可能只是"刷新**已存在**的恢复 Buff"（`Refresh` 语义），
> 在没有活动恢复 Buff 时是空操作。
>
> **不能作为单部位恢复接口使用。**
> 原风险 R7（左右肢体共享恢复效果）因此**不成立/无意义**——因为它根本不产生效果。

## 4. 实验 C：`SetToDefaultBodyPart(int)` —— ⛔ 未执行

### 4.1 按要求先做的静态与反射调查

| 调查项 | 结果 |
|---|---|
| 查找方法全部调用位置 | ❌ **不可得**：IL2CPP 下所有托管代码编译为原生指令，interop 里只有 `il2cpp_runtime_invoke` 桩，**看不到任何调用点** |
| 追踪调用位置的参数来源 | ❌ 同上，无法进行 |
| 判断参数属于哪种索引空间 | ❌ **无法判定** |
| 是否修改 HP/伤口/流血/绷带/视觉 | ❌ 无法从签名判断（同类里既有视觉方法也有状态方法） |
| 是否影响装备/衣物/其他角色 | ⚠ 发现同签名风格方法 `OnUnEquipClothing(int bodypartIndex)`，说明 `bodypartIndex` 也用于**衣物**语境 |

### 4.2 唯一可得的证据

- 参数名是 `bodypartIndex`，**不是** `bodyPartId`（后者已被实验证实是 0..5）；
- 同一类里 `OnUnEquipClothing(int bodypartIndex)` 也用这个名字；
- `GetBodyPartByIndex(int index)` 的 `index` 指向**视觉组件**（11 个，已证）。

### 4.3 处置

**按批准要求："只有参数空间得到可靠证据后，才可以在备份存档上进行单次针对性验证。禁止盲目遍历参数。"**

→ **未获得可靠证据 ⇒ 未执行调用。**
→ **R1 保持阻塞**，`SetToDefaultBodyPart` 继续禁止用于恢复方案。
