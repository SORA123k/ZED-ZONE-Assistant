### 1.3 【重要】两次会话的对比

| 项 | 会话 A | 会话 B | 说明 |
|---|---|---|---|
| 玩家指针 | `0x217D1CC7000` | `0x2A05F8D9000` | **不同对象**，证明不能缓存 |
| `appliedBodyPartConstitution` | 20 | 16 | 角色状态不同 |
| 头部 maxHP | 100 | **84** | **逐会话变化** |
| 躯干 maxHP | 130 | **114** | 同上 |
| 左臂/右臂 maxHP | 110 / 110 | **94 / 94** | 同上 |
| 左腿/右腿 maxHP | 120 / 120 | **104 / 104** | 同上 |
| `defaultHPAry` | [20,50,30,30,40,40] | [20,50,30,30,40,40] | **常量** |

**结论（实机）**：肢体 `maxHP` **随角色状态变化**（130→114 等），而 `defaultHP` 是固定常量。
→ 再次证明：**必须每次重新读取 maxHP；绝不能把 `defaultHP` 当回满目标。**

## 2. 数据侧静态表（实机读取，只读）

```
humanBodyPartTextIdAry      = [80, 81, 180, 181, 182, 183]
  -> 对应名称               = [头部, 躯干, 左臂, 右臂, 左腿, 右腿]
humanBodyPartDefaultHPAry   = [20, 50, 30, 30, 40, 40]
```

这解决了"数据数组顺序"的问题：**数据下标 0..5 ≠ 部位名称顺序的猜测**，而是由游戏自己给出的文本 ID 数组顺序决定，
且与 `bodyPartId`（0..5）一一对应。
