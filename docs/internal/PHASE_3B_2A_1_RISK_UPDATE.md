## 1. 已解除 / 已排除

### ✅ R3 解除：`HealAllBodyPartInjuries()` 是真的 HP 恢复

**实测**：躯干 22.428→138、左臂 109.558→118、左腿 64.13→128、右腿 64.385→128，
四个上限互不相同，各自回到**自己的** maxHP；`isWounded`/`isFullyRecovered` 同步；
**整体 HP 2160→2160 不变**。

→ 原来的"可能只改贴图"的担忧**不成立**。
→ **可以作为"恢复全部肢体"的实现路径。**

### ✅ R7 排除：`RefreshBodyPartRecoveryBuff` 无效果

**实测**：调用后六部位数据 **完全未变**，buff 数 3→3；
30 秒观察期内，目标部位（右腿 +1.934）与对照部位（左腿 +1.934）**涨幅完全相同**（各 1.51%）。

→ "左右腿共享恢复 Buff 导致连带"的问题**不存在**，因为这个接口根本没产生效果。
→ **不能作为单部位恢复接口，已排除。**

## 2. 仍未解决

### ⛔ R1：`SetToDefaultBodyPart(int bodypartIndex)` 参数空间

**本轮按批准要求做了静态与反射调查，结论是：无法获得可靠证据。**

| 调查项 | 结果 |
|---|---|
| 调用点 | ❌ IL2CPP 下不可得（interop 只有 invoke 桩） |
| 参数来源追踪 | ❌ 不可行 |
| 参数语义 | ❌ 无法判定（`bodypartIndex` 同时出现在 `OnUnEquipClothing` 的衣物语境） |

→ **未执行调用**（遵守"禁止盲目遍历参数"）。
→ **该接口仍不得进入恢复方案。**

### 🟡 R4：直写 `hp` 与绷带的同步

实测发现：`HealAllBodyPartInjuries()` 调用后**绷带不会立即消失**，
`bandaged` 在 0s/2s 仍为 1，**到 6s 才变为 0**。

含义：
- 原生接口的清理是**异步**的（由游戏后续 tick 处理）；
- 若我们**直接写 hp**，很可能**不会**触发这套清理 → 会留下"满血但仍挂着绷带"的状态。

→ 直写方案的这条风险**依然存在**，且比上一阶段判断得更具体。

### R2 / R6：维持原状

- **R2** `GetRecoveryBuffId` 越界静默返回 37 —— 不变，调用前必须自校验范围；
- **R6** `IsBodyPartWounded` 与 `isWounded` 冲突 —— 不变，统一用 `isWounded`。

### R5 / R9 / R10 / R11 / R12

维持上一版的风险描述与缓解措施，本轮无新证据。

## 3. 新增风险

### 【新增】R13：`HealAllBodyPartInjuries()` 会清除 Buff（3 → 0）

**实测**：调用前后 `buffCount` 从 **3** 变为 **0**。

- 可能是清掉了伤口类 Debuff（21–24）——属预期；
- 但**无法确认被清除的是哪几个**（本轮未记录 Buff ID）；
- 若其中包含**有益 Buff**，那就是副作用。

**影响**：中。对"恢复"语义而言可能合理，但必须让用户知情。

**缓解**：
1. 下一阶段在调用前**记录全部 Buff ID**，再判断清掉了什么；
2. UI 上提示"恢复全部肢体会同时清除绷带与部分 Buff"。

### 【新增】R14：绷带移除是延迟的（约 6 秒）

- 0s/2s：`bandaged=1`；6s：`bandaged=0`；
- 期间数据是"满血 + 仍绑着绷带"；
- 若用户在此期间再次点击恢复，可能重复处理。

**缓解**：恢复后不要立即重复调用；UI 上可提示"绷带将在数秒内自动解除"。

### 【新增】R15：存档持久化未验证

实验改变了肢体 HP，但**未执行"保存→回主菜单→读档"**流程，
因此无法确认恢复结果是否被正确写盘。

**缓解**：3B-2B 必须先做一次读档验证。

### 【新增】R16：**没有可用的原生"单部位恢复"接口**

- `RefreshBodyPartRecoveryBuff` ❌ 无效；
- `SetToDefaultBodyPart` ⛔ 无证据；
- `TickRecover` ❌ private；
- `OnSleepTimeUpdate` / `OnAwakeTimeUpdate` 语义是"时间推进"，不适用。

→ **单部位恢复目前只能靠"直接写 `bodypartDataAry[i].hp = maxHP`"**，
而这属于绕过原生逻辑，必须单独实测其副作用（绷带/流血/贴图）。

**影响**：高（直接决定"单独恢复指定部位"能不能做）。

## 5. 对下一阶段（3B-2B）的建议

| 建议 | 理由 |
|---|---|
| **"恢复全部"可以直接采用 `HealAllBodyPartInjuries()`** | 已实测：真恢复、逐部位动态上限、不动整体 HP、自动清绷带 |
| **"恢复单个"必须先解决 R16** | 原生路径全灭；只能评估"直写 hp"并实测其副作用 |
| 直写 hp 实测时**必须同时观察** `bandaged` / `isBleeding` / 贴图 | 这些不会像原生接口那样被自动清理 |
| 任何恢复操作前后**记录 Buff ID 列表** | 解决 R13 的未知 |
| 必须补一次**保存→读档**验证 | 解决 R15 |
| `SetToDefaultBodyPart` 继续禁用 | R1 未解除 |
| UI 文案必须告知"会清 Buff / 会解除绷带" | R13/R14 |
