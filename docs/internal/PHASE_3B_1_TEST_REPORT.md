## 2. 逐项测试结果

### T1 六个部位显示正确 ✅ 实机通过

- 数量 6，与 `bodypartDataAry.Length` 一致；
- 名称 `头部 / 躯干 / 左臂 / 右臂 / 左腿 / 右腿` 来自 `TextManager.GetText(humanBodyPartTextIdAry[i])`，
  与本地化表 ID 80/81/180/181/182/183 完全对应；
- **未使用任何硬编码名称**。

### T2 当前 HP 与实际数据一致 🟡 部分

**已验证**（算术一致性，全部吻合）：

| 部位 | hp / maxHP | 计算百分比 | 界面显示 |
|---|---|---|---|
| 躯干 | 72.95 / 134 | 54.44% | **54%** ✓ |
| 左腿 | 115.57 / 124 | 93.20% | **93%** ✓ |
| 右腿 | 85.45 / 124 | 68.91% | **69%** ✓ |
| 头部 | 104 / 104 | 100% | **100%** ✓ |

**未验证**：与游戏原生肢体面板**同屏逐项对照**（需要人工同屏截图）。
另：本次 `LimbProbe` 已按上阶段要求关闭，因此没有同源的 `[limb]` 日志可供交叉比对。

### T3 最大 HP 动态变化后 UI 更新 ✅ 实机通过

四个不同时间点读到的肢体上限（同一角色槽位）：

| 时间 | appliedBodyPartConstitution | 头部 | 躯干 | 左臂 | 右臂 | 左腿 | 右腿 |
|---|---|---|---|---|---|---|---|
| 23:21 | 20 | 100 | 130 | 110 | 110 | 120 | 120 |
| 23:42 | 16 | 84 | 114 | 94 | 94 | 104 | 104 |
| 00:00 | 20 | **104** | **134** | **114** | **114** | **124** | **124** |

- 上限确实随角色状态变化（甚至 constitution 同为 20 时也有 100→104 的差异）；
- UI 每次都显示**当次读取值**，没有任何缓存；
- **未验证**：同一次会话内上限发生变化时 UI 的即时刷新（未构造该场景）。

### T4 受伤状态正确 ✅ 实机通过（**并发现一个此前的错误结论**）

实测：`54%` 与 `69%` → 显示"受伤"；`93%` → 显示"正常"。

**这推翻了此前文档中的假设** `isWounded == (hp < maxHP)`——
若按该假设，93% 应当也是"受伤"。

**更正后的结论**：`isWounded` 是**带阈值**的派生属性，阈值介于 **69% 与 93% 之间**（未精确测出）。
`isFullyRecovered` 仍表现为"接近满值才为真"（93% 时为 0）。
`hpFloat == hp/maxHP` 的结论**仍然成立**（本次 3 个非满值部位全部吻合）。

> 已同步在 `PHASE_3B_0_ENUMERATION_REPORT.md` §2.4 加注更正。

### T5 流血状态正确 ❌ 未验证

本次所有采样 `isBleeding` 均为 0，界面上"流血 0"正确反映了数据，
但**没有观察到 `isBleeding=1` 的真实样例**，因此"流血时显示为红色'流血'"这条**未经实机验证**。

### T6 场景切换后重新获取数据 ❌ 未执行

**原因**：需要游戏内走位穿越场景；本会话的自动化输入会与游戏自身热键冲突
（实测：数字键被游戏物品栏吞掉，见 §6），因此**主动停止输入注入**。
未做"进出建筑后数值/对象是否更新"的对照。

已具备的间接证据：每次刷新（100 ms）都会重新 `Resolve()` 玩家对象，且
`[state] 玩家对象消失（场景=Loading）` 与 `[limb] 玩家对象消失` 路径已在 3B-0.1 验证。

### T7 玩家对象失效时安全处理 ✅ 实机通过

主菜单场景下（`GameController.playerCharacter == null`）面板行为：

```
无法读取肢体数据：未找到玩家对象（主菜单 / 加载中 / 已死亡未重生）
这是正常状态：进入存档后会自动显示，不会使用上一次的旧数据。
```

- 不显示任何旧的肢体数值；
- 不抛异常（`[Error]` = 0）。

### T8 死亡/重生不使用旧引用 ❌ 未验证

未发生死亡（`deadFlag` 全程 0）。代码层面每次刷新都重新解析、玩家为空即清空列表，

## 7. 测试过程中的一次副作用（如实记录）

结果该按键被**游戏自身**当作物品栏/快捷栏热键处理，导致游戏打开了背包界面。
- 未造成数据损坏（未写入任何数值、未使用物品失败日志）；
- 之后我**停止了所有输入注入**，改用 `[UI] StartTab` 配置直接打开指定页；
- 你随后手动关闭面板，我一度误判为崩溃，经检查 `Player.log` 无崩溃标记、`[Error]=0`，确认是手动关闭。
