## 1. R13（已缓解）：清除的是"过期的恢复类 Buff"

**实测**：调用前 3 个 Buff，全部为恢复类且**剩余时间为负（已过期）**：

| ID | 名称 | isDebuff | 剩余 |
|---|---|---|---|
| 35 | torseRecovery | 0 | -5.16s |
| 37 | legRecovery | 0 | -5.16s |
| 36 | armRecovery | 0 | -5.09s |

调用后 → **0**，且 10 秒内未重建。

**为什么算"缓解"而不是"排除"**：
- 本次样本里**不存在**无关的、正在生效的有益 Buff；
- 因此无法证明"它不会清有益 Buff"；
- 只能证明：**在当前样本中，它只清掉了与受伤部位对应的、过期的恢复类 Buff**（语义合理）。

**剩余风险**：若玩家身上有正在生效的增益，恢复全部是否会把它们一起清掉 —— **未知**。

**缓解建议（若实现）**：
1. UI 文案避免"不影响任何状态"这类绝对表述；
2. 若后续实测发现清增益，需要在按钮上明确警告。

## 3. R15（仍未验证）：持久化测试**无效**，需重做

**用户说明（已采纳）**：本次对比无效 —— 我在实验后**强制结束了游戏进程，没有走游戏自身的保存流程**，
玩家状态（含肢体）并未真正存盘。

**这解释了全部矛盾**：重载得到的既不是治疗前数值，也不是治疗后数值，而是更早的某个已存盘状态。

**实验方法缺陷（我方责任）**：
1. 强杀进程 ≠ 正常退出；
2. 未在游戏内执行显式保存；
3. 实验到退出之间角色仍在战斗。

→ 本轮数据**不可引用**。R15 维持 **【尚未验证】**。

**已能确认的（间接）**：上一阶段强杀后重载，六部位还原出
**22.428 / 109.558 / 64.13 / 64.385** 这些精确小数 →
**肢体 HP 确实被序列化**，机制存在。

**重做条件（必须全部满足）**：
1. 在**无敌人**的安全区进行；
2. 恢复后**在游戏内显式保存**（菜单保存或睡眠等游戏内保存点）；
3. 保存后**正常退出**（不是强杀）；
4. 重载后立即记录六部位 + Buff；
5. 全程不战斗、不移动。

**需要用户配合**：请告知游戏内手动保存的操作方式（键位/菜单/睡觉），
或由你在我完成恢复后手动保存一次，我再读取重载结果。

## 4. R16（未变）：没有可用的原生单部位恢复接口

- `RefreshBodyPartRecoveryBuff` ✅ 已实测**无效果**；
- `SetToDefaultBodyPart` ⛔ 参数空间无证据，禁止调用；
- `TickRecover` private，不可调用；
- `OnSleepTimeUpdate` / `OnAwakeTimeUpdate` 语义是时间推进，不适用。

→ 单部位恢复仍只能考虑"直接写 `bodypartDataAry[i].hp`"，而该方案**未获批准、未验证**。

## 5. 新增/补充观察

### 【补充】肢体 maxHP 随升级再次变化
本轮重载时：头部 108→112、躯干 138→142、手臂 118→122、腿 128→132；
整体 maxHP 2160→2240；`conGained` 3→4。

→ 与 Phase 3A 的结论一致：**肢体上限是动态的，必须每次重读**。
→ 也意味着"恢复后再读到的上限可能已不同于恢复时"。

### 【新增】实验环境干扰：战斗会污染持久化对比
本次持久化测试失败的直接原因是"实验与保存之间角色仍在战斗"。

**建议纳入后续实验规范**：
1. 实验前进入无敌人区域；
2. 保存/重载对比期间不要移动、不要战斗；
3. 记录存档文件时间戳作为"确实保存过"的客观证据。
