**【已通过源码确认】** / **【已通过实机验证】** / **【尚未验证】** / **【存在风险】**

## 1. 设计目标与边界

| 项 | 说明 |
|---|---|
| 目标 | 新增独立「肢体」页，只读展示六个部位的状态 |
| 边界 | **不写任何游戏数据、不调用任何恢复接口、不装 Harmony 补丁** |
| 数据源 | `CharacterData.bodypartsData → bodypartDataAry → CharacterBodyPartData` |
| 名称源 | `humanBodyPartTextIdAry[i] → TextManager.GetText()` |
| 联机 | **整块禁用**（只显示提示，不展示数据） |

### 1.1 明确禁止（设计红线）

| 禁止 | 原因 |
|---|---|
| 用视觉组件下标当数据索引 | 已证实视觉 11 个 / 数据 6 个，顺序不同 |
| 直接相信 `bodypartDataID` | 2/11 与名称不一致 |
| 用 `defaultHP` 当最大 HP | 实测 constant [20,50,30,30,40,40] ≪ maxHP |
| 缓存跨场景/跨重生的对象 | 玩家指针每次会话都变 |
| 使用固定最大 HP | 实测 4 次会话得到 4 组不同上限 |

## 2. 面板结构

新增第 7 个标签页「肢体」，位于「状态」与「设置」之间：

```
1.玩家  2.生命  3.饱食  4.水分  5.体力/精力  6.状态  7.肢体  8.设置
```

### 2.1 页面布局

```
肢体状态（只读）　场景=Gaming                       ← 标题行
共 6 个部位　受伤 2　流血 0　完全恢复 3              ← 概览行（有未知时追加"未知 N"并转黄）
部位　　　当前 / 上限　　　百分比　　　状态          ← 列头
头部　　 104 / 104　　　[████████] 100%　已恢复
躯干　　 72.95 / 134　　[████░░░░] 54% 　受伤
左臂　　 114 / 114　　　[████████] 100%　已恢复
右臂　　 114 / 114　　　[████████] 100%　已恢复
左腿　　 115.57 / 124　 [███████░] 93% 　正常
右腿　　 85.45 / 124　　[█████░░░] 69% 　受伤
只读展示，不会修改任何数值。                        ← 页脚声明
```

### 2.2 每行字段

| 列 | 内容 | 缺失时 |
|---|---|---|
| 部位 | `TextManager.GetText(humanBodyPartTextIdAry[i])` | `未知(TextId=x)` |
| 当前 / 上限 | `hp` / `maxHP` | `?` |
| 百分比 | `hp/maxHP`，条 + 文字 | `?`，**条只画背景不画填充** |
| 状态 | 受伤 / 流血 / 已恢复 / 正常 | `读取失败(...)` 或 `未知（上限无效）` |

### 2.3 颜色语义

| 条件 | 颜色 |
|---|---|
| 百分比 ≥ 99.9% | 绿 |
| ≥ 50% | 黄 |
| < 50% | 红 |
| 数值缺失 | 只画灰底，不画填充 |

> 颜色只用于**条**，不改变文字含义；文字始终是权威表达。

## 3. 刷新策略

| 项 | 设计 |
|---|---|
| 频率 | 与既有玩家快照**同频**（默认 100 ms，`[Read] RefreshIntervalMs`） |
| 实现方式 | 在 `AssistantPanel.Update` 的节流块内调用 `LimbData.Refresh()`，**不是每帧** |
| 封送次数 | 每次刷新约 6 部位 × 8 字段 ≈ 50 次只读 interop |
| 日志 | **本页不产生任何日志**（避免刷屏） |
| OnGUI | 只是读内存快照 + 画，不做 interop |

**为什么不在 OnGUI 里读**：OnGUI 每帧多次执行，直接在里面对 IL2CPP 对象封送会造成明显的 GC 与卡顿；
这与 Phase 2 的"薄 MonoBehaviour"原则一致。

## 4. 异常与边界处理

| 情况 | 表现 |
|---|---|
| 玩家对象不存在（主菜单/加载/死亡未重生） | 显示"无法读取肢体数据：<原因>"+"这是正常状态：进入存档后会自动显示，**不会使用上一次的旧数据**" |
| `characterData` / `bodypartsData` / 数组 为 null | 同上，原因具体到哪一层 |
| 数组长度为 0 | "肢体数据为空：<原因>" |
| 单个部位读取失败 | 该行显示"读取失败"，其余行正常 |
| `maxHP <= 0` 或 NaN | 该行百分比显示 `?`，状态显示"未知（上限无效）" |
| 联机 | 顶部红字"联机模式：肢体管理已禁用（原因）"，**不渲染任何部位数据** |

## 6. 安全设计

1. **只读**：`LimbData` 只读字段并构造本地快照，源码中无任何对游戏对象的赋值；
2. **不调用恢复接口**：未引用 `HealAllBodyPartInjuries` / `SetToDefaultBodyPart` / `RefreshBodyPartRecoveryBuff` / `UseBandage` / `RemoveBandage`；
3. **不装补丁**：`[HarmonyPatch]` 计数仍为 0；
4. **联机禁用**：复用已实机验证的 `NetworkManager` 判定，fail-closed；
5. **不缓存**：每次刷新重新 `Resolve()` 玩家；玩家消失即清空，页面转"无法读取"。
