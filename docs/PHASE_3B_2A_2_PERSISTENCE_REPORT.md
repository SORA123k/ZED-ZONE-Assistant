## 1. R14：绷带延迟行为

### 1.1 时序数据（同一实验，六部位逐点记录）

| 时刻 | 躯干 bandaged | 左臂 | 左腿 | 右腿 | HP（六部位） |
|---|---|---|---|---|---|
| **0s**（调用后立即） | 1 | 1 | 1 | 1 | 全部 = 各自 maxHP |
| **+2s** | 1 | 1 | 1 | 1 | 全部 = maxHP |
| **+4s** | 1 | 1 | 1 | 1 | 全部 = maxHP |
| **+6s** | **0** | **0** | **0** | **0** | 全部 = maxHP |
| **+10s** | 0 | 0 | 0 | 0 | 全部 = maxHP |

（头部/右臂在调用前就没有绷带，全程 0）

### 1.2 结论

- 绷带**不是**立即移除，而是在**第 4 秒到第 6 秒之间**被移除；
- 与 Phase 3B-2A.1 的观察（6s 时为 0）**一致**；
- **无法证明是"固定延迟"还是"由游戏下一次状态刷新触发"** —— 因为没有第二个不同时间起点样本；
- 按要求**未修改任何计时器或内部状态**来加速实验。

### 1.3 期间的数据状态

0~4 秒内是 **"HP 已满 + 仍标记为已包扎"** 的中间态。
此时若再次点击恢复，可能对同一部位重复处理 → 已作为 R14 风险保留。

## 2. R15：存档持久性

### 2.1 实验流程

| 步骤 | 结果 |
|---|---|
| 1. 记录恢复前数据 | 躯干 22.428/138、左臂 109.558/118、左腿 64.13/128、右腿 64.385/128 |
| 2. 执行一次全恢复 | 全部回到各自 maxHP（见 R13 报告） |
| 3. 记录恢复后数据 | 六部位全部满值、bandaged 6s 后为 0、buffCount 0 |
| 4. **正常游戏流程保存** | 游戏在 **00:45:50** 自动写盘 `26e8f5e0-..._SlotIndex5.game`（实验约在 00:44:50） |
| 5. 退出并重新进入 | 退出进程 → 重新启动 → 载入同一存档 |
| 6. 再次读取 | 见 §2.2 |
| 7. 对比 | 见 §2.3 |

### 2.2 重载后的实际数据


### 2.3 对比与判定

| 部位 | 恢复后 | 重载后 | 判断 |
|---|---|---|---|
| 头部 | 108/108 满 | 109.009/**112** wounded=0 | 上限变了（升级） |
| 躯干 | 138/138 满 | **29.882**/142 wounded=1 | ❌ 不是满值 |
| 左臂 | 118/118 满 | **122/122 满** | ✅ 保持满值 |
| 右臂 | 118/118 满 | **122/122 满** | ✅ 保持满值 |
| 左腿 | 128/128 满 | **107.798**/132 wounded=1 | ❌ 不是满值 |
| 右腿 | 128/128 满 | **48.388**/132 wounded=1 | ❌ 不是满值 |

**体会上限全部变化**：108→112、138→142、118→122、128→132
（同时角色升级：`conGained` 3→4，整体 maxHP 2160→2240）
→ 再次印证**肢体 maxHP 是动态的**，且随升级提升。

### 2.4 为什么无法定论

**用户说明（本报告采纳）**：本次重载对比**无效**，原因是
**我在实验后强制结束了游戏进程，没有通过游戏自身的保存流程存盘**，
因此玩家状态（含肢体）并未被真正写入存档。

**这一点解释了全部矛盾数据**：
- `.game` 文件在 00:45:50 有写入，但那不是"我期望的那次玩家状态保存"；
- 重载出来的数值既不是治疗前（22.428/64.13/64.385），也不是治疗后（满值），
  而是**更早的某个已存盘状态**（同时上限已变为 142/132/112/122）；
- 因此**本轮数据不能用于判断"治疗是否持久化"**。

**实验方法的问题（我方责任）**：
1. 强杀进程 ≠ 正常退出；
2. 没有在游戏内执行一次显式保存；
3. 实验与退出之间角色还在战斗，状态被进一步污染。

→ 按"不得猜测"的要求，R15 标记为 **【尚未验证】**，
并明确记录本次为**无效实验**，不可引用为结论。

### 2.5 仍然可以确认的一点（间接）

上一阶段（3B-2A.1）实验后**强制结束进程**、未存档、再重载时，
六部位恢复出 **22.428 / 109.558 / 64.13 / 64.385** —— 与治疗前的原始小数**完全一致**。

这证明：**肢体 HP 确实会被写进存档并在载入时还原**（否则不会出现这些精确小数）。
即**序列化机制存在**，缺的是"通过游戏自身保存流程、在无战斗干扰下"的干净样本。

### 2.5 已经可以确认的一点（间接）

上一阶段（3B-2A.1）实验后**强制结束进程**、未存档、再重载时，
六部位恢复出 **22.428 / 109.558 / 64.13 / 64.385** —— 与治疗前的原始小数**完全一致**。

这证明：**肢体 HP 确实被写进存档并在载入时还原**（否则会显示满值或默认值）。

## 4. 额外检查：不同整体 HP 下的行为

| 实验 | 调用前整体 HP | 调用后整体 HP | 是否不变 |
|---|---|---|---|
| 3B-2A.1 实验 A | 2160 | 2160 | ✅ |
| 3B-2A.2 实验 A2 | 2160 | 2160 | ✅ |

两次样本的**肢体损伤分布不同**（一次 4 个受伤部位，一次 4 个也是但数值不同），
整体 HP 均保持 2160 不变。

**局限**：两次的整体 HP 恰好相同（2160），**没有取到"不同整体 HP"的样本**，
因此"在任意整体 HP 下都不变"仍属 **【尚未验证】**（只验证了同一整体 HP 下的两次）。
