## 3. 【存在风险】视觉索引与数据索引不一致

**实测**：

| 数据 index | 数据 bodyPartId | 视觉 index 的 bodypartDataID | match |
|---|---|---|---|
| 0 头部 | 0 | 1 | **MISMATCH** |
| 1 躯干 | 1 | 4 | **MISMATCH** |
| 2 左臂 | 2 | 4 | **MISMATCH** |
| 3 右臂 | 3 | 5 | **MISMATCH** |
| 4 左腿 | 4 | 5 | **MISMATCH** |
| 5 右腿 | 5 | 0 | **MISMATCH** |

**含义**：
- `bodypartDataAry[i]`（数据层）与 `GetBodyPartByIndex(i)`（视觉组件层）**不是同一索引空间**；
- 两者之间既非相等、也非固定偏移（值 1,4,4,5,5,0 有重复）。

**风险（直接关系未来功能）**：
- `SetToDefaultBodyPart(int bodypartIndex)` 的 `bodypartIndex` 到底指哪个空间 → **未知**；
- 若猜错，会"恢复头部"却实际改了别的部位 —— 与 Phase 3A 的 HP 截断 Bug 属同类错误。

**处置**：该风险已登记为 3B-2（肢体恢复）的**前置阻塞项**，在确认 `SetToDefaultBodyPart` 的索引语义前不得使用它。

## 4. A–E 附加验证评审

### A. 数据实时性 ✅ 通过（采样精度内）

证据：肢体自然恢复在连续采样中被逐个捕获（92.55→92.66→92.77，间隔 0.5s）。
→ `hp` 是持续更新的实时字段；**未发现 Tick 延迟**（在 500ms 采样精度下）。
状态属性同帧更新（同一行输出）。

**限制**：未观察到"受伤瞬间"（需人工造成伤害）→ 受伤的实时性仍属 **未验证**。

### B. 状态关联 ✅ 通过

数值吻合：
- 躯干 92.55/130 = 0.7119 → `hpFloat=0.71` ✔
- 左腿 94.13/120 = 0.7844 → `0.78` ✔
- 右腿 64.01/120 = 0.5334 → `0.53` ✔
- 满血三部位：`hpFloat=1, isWounded=0, isFullyRecovered=1` ✔

**未发现**其它独立状态数据影响这三个属性（源码中它们只有 getter）。
`isBleeding` 在本次样本中全为 0，**未观察到流血** → 该项 **未验证**。

### C. 存档持久化 🟡 仅源码确认

- 【已通过源码确认】`CharacterData.bodypartsData` 是普通字段，随 `CharacterData` 一起存在于角色数据中；
- 【已通过源码确认】存在 `HumanCharacterController.LoadBodyparts()` 与 `CharacterData.RefreshBodyPartsStatus()`；
- 【尚未验证】肢体 hp 是否真的写入存档、读档后是否恢复 —— **未做存档前后对比**。

### D. 对象生命周期 🟡 部分通过

- ✅ 每次采样都重新 `PlayerAccessor.Resolve()`，**不缓存**
- ✅ `MainMenu(player=null)` → `Gaming(player=...)` 触发"重新枚举"，并打印新 `ptr`
- ✅ 玩家消失时清空上一轮缓存
- ⚠ 死亡/重生后旧引用是否失效、是否抛异常 → **未验证**（需人工死亡）

### E. 名称映射 ✅ 通过

- ✅ `textId` 来自 `bodyPartTextId`（数据），名称来自 `TextManager.GetText(textId)`（游戏本地化）
- ✅ 结果 `头部/躯干/左臂/右臂/左腿/右腿` 与本地化表 ID 80/81/180/181/182/183 对应
- ✅ **没有按 index 猜名称**
- ⚠ "与游戏原生面板逐条同屏对照"未做 → 未验证（但已由本地化来源保证）
